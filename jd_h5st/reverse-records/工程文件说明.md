# 京东 h5st 项目文件说明

## 1. 项目概述

本项目用于分析京东搜索接口的请求签名，并在本地生成 `h5st`，替换测试请求中的旧签名值。

项目主要包含：

- Python 请求测试代码
- Node.js 本地签名封装
- 浏览器环境补丁
- JavaScript 混淆还原脚本
- SDK 原始文件和还原文件
- 逆向过程记录与分析报告

## 3. 请求测试文件

### 3.1 test.py

文件路径：

```text
test.py
```

这是 Python 请求入口，负责：

1. 配置京东 Cookie 和请求 headers。
2. 构造搜索请求 body。
3. 对 body 做 SHA-256。
4. 调用本地 Node.js 签名脚本。
5. 获取本地生成的 `h5st`。
6. 读取或设置 `x-api-eid-token`。
7. 组装最终请求参数。
8. 使用 `requests.get()` 请求京东接口。

核心流程：

```text
search_body
  -> JSON 序列化
  -> SHA-256
  -> 组合签名输入
  -> 调用 env/sign.js
  -> 获取 h5st
  -> 组装请求 URL
  -> 请求京东接口
```

关键代码位置：

| 位置 | 作用 |
|---|---|
| 第 75 行附近 | `sign_query()` 本地签名函数 |
| 第 85 行附近 | 调用 Node.js 签名脚本 |
| 第 112 行附近 | body 序列化和时间戳生成 |
| 第 116 行附近 | 设置 `api_eid_token` |
| 第 122 行附近 | 组装最终请求参数 |
| 第 138 行附近 | 发起京东 GET 请求 |

该文件包含登录 Cookie 和动态 token，不应提交到公开仓库。

## 4. Node.js 签名文件

### 4.1 env/sign.js

这是本地签名核心封装，负责：

1. 创建 Node.js VM 沙箱。
2. 模拟 `window`、`navigator`、`document` 等浏览器对象。
3. 加载浏览器环境补丁。
4. 加载还原后的 `ParamsSign` SDK。
5. 创建签名实例。
6. 调用 `signSync()`。
7. 返回 `h5st`、`_stk`、`_ste` 等字段。

签名实例：

```javascript
new window.ParamsSign({
  appId: 'f06cc',
  preRequest: false
})
```

输入对象通常包含：

```javascript
{
  appid,
  functionId,
  client,
  clientVersion,
  t,
  body
}
```

该文件是 `test.py` 直接调用的本地签名程序。

### 4.2 env/server.js

这是可选的本地 HTTP 签名服务。

默认地址：

```text
http://127.0.0.1:3456/sign
```

接口为 `POST /sign`，负责将 `sign.js` 包装为 HTTP 服务，方便其他程序调用。

启动：

```powershell
node env/server.js
```

当前 `test.py` 已改为直接调用 `sign.js`，正常测试时不需要启动此服务。

### 4.3 env/run.js

这是 SDK 独立验证脚本，用于确认 Node.js 补环境和 SDK 是否可以正常工作。

主要功能：

- 加载浏览器环境补丁
- 加载还原后的 SDK
- 创建测试签名实例
- 输出 SDK 状态和签名摘要
- 输出执行错误

运行：

```powershell
node env/run.js
```

该文件只用于调试验证。

## 5. SDK 文件

### 5.1 reverse-records/js_security_v3_0.1.6.original.js

这是从京东页面获取的原始混淆 SDK，包含：

- `ParamsSign` 实现
- `sign()` 和 `signSync()` 入口
- VM 栈机逻辑
- token 刷新逻辑
- 环境指纹逻辑
- 混淆字符串和字节码

它是 AST 还原的输入文件，不直接用于当前签名运行。

### 5.2 source/deobfuscated/js_security_v3_0.1.6.readable.js

这是经过 AST 还原和格式化后的 SDK 阅读版，包含：

- `ParamsSign` 类定义
- `sign()` 异步入口
- `signSync()` 同步入口
- `_$sdnmd()` VM 执行入口
- `_$ram()` token 刷新入口
- `h5st` 生成逻辑
- 指纹和环境读取逻辑

这是 `env/sign.js` 实际加载的 SDK 文件。部分 VM 字节码和栈机结构仍被保留，以避免破坏运行语义。

## 6. 中间产物

### 6.1 intermediate/js_security_v3_0.1.6.step1_strings.js

第一阶段字符串还原结果。

处理内容：

- 解析原始混淆 JavaScript
- 恢复 `_4vve5()` XOR-5 字符串解码调用
- 输出第一阶段代码

作为第二阶段脚本的输入。

### 6.2 intermediate/js_security_v3_0.1.6.step2_runtime_strings.js

第二阶段运行时字符串还原结果。

处理内容：

- 提取 `a03438dp/mj` 解码器
- 在隔离 VM 中执行解码逻辑
- 恢复运行时动态字符串
- 输出第二阶段代码

作为最终整理脚本的输入。

### 6.3 intermediate/js_security_v3_0.1.6.report.json

AST 处理统计报告，包含：

- 原始文件大小
- 输入输出行数
- 字符串恢复数量
- 常量折叠数量
- VM 字节码数组统计
- SDK 入口信息
- 尚未还原的部分
- 各阶段文件路径

不参与签名运行。

## 7. AST 还原脚本

### 7.1 scripts/deobfuscate_params_sign.js

第一阶段 AST 处理脚本。

功能：

- 使用 Babel 解析 JavaScript
- 查找 `_4vve5()` 字符串解码调用
- 执行 XOR-5 解码
- 将结果替换回 AST
- 生成第一阶段中间文件
- 统计混淆结构

输入：`reverse-records/js_security_v3_0.1.6.original.js`

输出：`intermediate/js_security_v3_0.1.6.step1_strings.js`

### 7.2 scripts/restore_params_sign_runtime_strings.js

第二阶段运行时字符串还原脚本。

功能：

- 定位 `a03438dp/mj` 解码器
- 提取解码器初始化代码
- 在隔离 VM 中执行解码器
- 恢复运行时字符串
- 生成第二阶段中间文件

输入：第一阶段字符串还原文件。

输出：`intermediate/js_security_v3_0.1.6.step2_runtime_strings.js`

### 7.3 scripts/finalize_params_sign_readable.js

最终 SDK 整理脚本。

功能：

- 折叠数值、字符串和布尔常量
- 规范化安全的对象属性访问
- 保留 VM 栈机结构
- 输出阅读版 SDK
- 生成处理统计报告

输出：

```text
source/deobfuscated/js_security_v3_0.1.6.readable.js
intermediate/js_security_v3_0.1.6.report.json
```

## 14. 安全注意事项

1. `test.py` 中包含登录 Cookie 和动态 token，不要公开发布。
2. 不要打印完整请求 URL，避免泄露 `h5st` 和 `x-api-eid-token`。
3. Cookie 和 token 失效后，需要在已登录浏览器中重新获取。
4. `x-api-eid-token` 依赖浏览器设备环境，不能简单由 `h5st` 算法生成。
5. Node.js 本地生成的 `h5st` 与浏览器生成值可能存在差异。
6. 本地签名成功不代表京东服务端一定接受请求。
7. 返回 `403` 时，优先检查 Cookie、token、时间戳、body 序列化和请求参数是否匹配。
