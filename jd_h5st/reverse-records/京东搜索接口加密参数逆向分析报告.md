# 京东搜索接口加密参数逆向分析报告

## 1. 报告概述

本报告记录京东搜索页接口的请求构造、`h5st` 签名、`x-api-eid-token` 动态令牌定位过程，以及 Node.js 本地复现和 Python 请求改造结果。

本次目标是在保留登录 Cookie、请求体和业务参数的前提下，将请求中抓包得到的旧加密值替换为运行时本地生成值。报告不保存完整登录 Cookie、`api_eid_token`、`h5st` 或其他可直接复用的敏感值。

## 2. 目标与请求契约

页面：

```
https://search.jd.com/Search?keyword=衣服&enc=utf-8
```

接口：

```
GET https://api.m.jd.com/api
```

主要参数：

| 参数 | 来源/示例 | 说明 |
|---|---|---|
| `appid` | `search-pc-java` | 搜索业务标识 |
| `functionId` | `pc_search_adv_Search` / `pc_search_searchWare` | 接口函数 |
| `client` | `pc` | 客户端类型 |
| `clientVersion` | `1.0.0` | 客户端版本 |
| `uuid` | Cookie `__jdu` | 设备/登录关联标识 |
| `keyword` | `衣服` | 搜索关键词 |
| `body` | JSON 字符串 | 业务请求体 |
| `x-api-eid-token` | Cookie `3AB9D23F7A4B3CSS` 或浏览器动态值 | 设备/登录环境令牌 |
| `h5st` | 本地 SDK 实时生成 | 请求签名 |
| `t` | 当前毫秒时间戳 | 签名时间参数 |

当前测试 body：

```json
{
  "ad_ids": "292:6",
  "xtest": "new_search",
  "ec": "utf-8",
  "area": "18",
  "page": "1",
  "simpleSearch": "0"
}
```

## 3. 浏览器侧调用链

通过 Network、XHR 断点和调用栈确认，完整链路为：

```
搜索页面动作
  -> 搜索业务函数 Bm
  -> xhr 请求封装
  -> Axios XHR adapter
  -> 最终 API URL
  -> x-api-eid-token = window.getJsToken(callback)
  -> h5st = window.PSign.sign(d).h5st
```

### 3.1 业务请求构造位置

- 脚本：`https://storage.360buyimg.com/retail-mall/main_search/pro/0.0.11/js/index.9f0c5ba0.js`
- 压缩脚本：第 10 行
- 运行时调用栈：约第 10 行、第 69652 列
- 请求函数：`Bm`，约第 74601 列
- XHR 封装：约第 67693 列
- 调用关系：`Bm -> xhr -> Axios XHR adapter`

断点命中时，Axios 请求配置中已经出现完整的 `x-api-eid-token` 和 `h5st`，说明两个值在进入 XHR adapter 之前已经完成注入。

## 4. h5st 签名分析

### 4.1 页面入口

页面初始化创建签名实例：

```javascript
window.PSign = new window.ParamsSign({
  appId: 'f06cc',
  preRequest: false
});
```

业务请求前调用：

```javascript
window.PSign.sign(d).h5st
```

`d` 的核心字段：

```javascript
{
  appid: 'search-pc-java';
  functionId: 'pc_search_searchWare';
  client: 'pc';
  clientVersion: '1.0.0';
  t: Date.now();
  body: SHA256(JSON.stringify(signBody))
}
```

最终 `test.py` 使用的 `functionId` 为 `pc_search_adv_Search`，因此本地签名输入同步使用该值。

### 4.2 SDK 入口

- SDK：`https://storage.360buyimg.com/webcontainer/js_security_v3_0.1.6.js?v=2024-06-20-17`
- 导出对象：`window.ParamsSign`
- 异步入口：`ParamsSign.prototype.sign`
- 同步入口：`ParamsSign.prototype.signSync`
- VM 入口：`ParamsSign.prototype._$sdnmd`
- token 刷新入口：`ParamsSign.prototype._$ram`

`signSync()` 返回对象包含：

```
appid, functionId, client, clientVersion, t, body, _stk, _ste, h5st
```

本地验证的 `_stk`：

```
appid,body,client,clientVersion,functionId,t
```

`_ste` 验证值为 `1`。

### 4.3 h5st 特征

本地无浏览器远程 token/指纹预热时：

- 长度约 859
- 分号分隔，共 10 段
- 字符以字母、数字、下划线和连字符为主
- 首段为毫秒时间戳形式

浏览器完整环境下同类结果约为 1171 字符。差异主要来自浏览器侧 token、fingerprint 和运行环境状态，不代表本地 VM 无法执行。

## 5. x-api-eid-token 分析

### 5.1 生成入口

- 脚本：`https://gias.jd.com/js/pc-tk.js?v=2024-06-20-17`
- 调用：`window.getJsToken(callback, 200)`
- 关联 Cookie：`3AB9D23F7A4B3CSS`

该值不是 `ParamsSign.sign()` 的输出，不能通过单独计算 `h5st` 得到。它属于登录态和浏览器设备环境相关的动态令牌。

### 5.2 环境依赖

令牌链路会读取或依赖：

- `navigator.userAgent`
- `navigator.languages`
- `navigator.webdriver`
- 屏幕信息和时区
- Web Storage
- Canvas/WebGL 等浏览器特征
- 页面 Cookie 和设备状态

因此抓包中的 token 具有时效性和会话关联性。失效后，需要在同一浏览器登录环境重新执行搜索并获取新值。

## 6. 混淆代码还原

SDK 原始文件属于字符串数组、控制流和栈机混合混淆，直接在原始压缩文件中搜索业务明文不可靠。

已完成：

1. 恢复 `_4vve5` XOR-5 字符串解码调用，共 255 处。
2. 在隔离 VM 中执行 `a03438dp/mj` 解码引导片段，恢复运行时字符串，共 263 处。
3. 对安全的数值、字符串、布尔常量进行折叠。
4. 保留 `_2hoe5` 字节码数组和 `_$sdnmd` 栈机，避免破坏运行语义。

[source/deobfuscated/js_security_v3_0.1.6.readable.js](../source/deobfuscated/js_security_v3_0.1.6.readable.js)


说明 SDK 可以在当前 Node VM 沙箱中加载并执行。

### 7.2 本地封装

[sign.js](../env/sign.js) 完成：

1. 创建 Node VM 沙箱。
2. 加载浏览器补环境模块。
3. 加载阅读版 `ParamsSign` SDK。
4. 创建 `ParamsSign({appId: 'f06cc', preRequest: false})` 实例。

[server.js](../env/server.js) 另提供可选的 `POST /sign` HTTP 中间层，默认端口为 3456，但最终 Python 测试不再依赖该常驻服务。

## 8. Python 测试实现

最终测试文件：

[test.py](../test.py)

实际流程：

```
构造 search_body
  -> JSON 紧凑序列化
  -> UTF-8 编码
  -> SHA-256
  -> 组合 ParamsSign 输入对象
  -> subprocess 调用 env/sign.js
  -> 读取 h5st
  -> 组装最终 query 参数
  -> requests.get(api.m.jd.com/api)
```

关键代码位置：

- `sign_query()`：第 75 行附近
- Node 脚本路径：第 62 行
- Node 可执行文件配置：第 63 行
- body 序列化和时间戳：第 112–114 行
- `api_eid_token`：第 116–120 行
- 最终 query 参数：第 122–136 行

默认使用 PATH 中的 `node`。如果 Python 环境找不到 Node.js：

```powershell
$env:JD_NODE = 'C:\\nvm4w\\nodejs\\node.exe'
python test.py
```

注意：当前 `test.py` 的 token/Cookie 属于本地登录态，不应提交到公开仓库。


Python 端已验证：

此前使用抓包旧状态测试时，京东接口返回过 `403`。这表示本地代码执行成功不等于服务端一定接受请求；服务端还会校验 Cookie、`x-api-eid-token`、设备环境、时间窗口和签名上下文。

## 10. 当前结论

### 已完成

1. 定位 `h5st` 业务调用入口。
2. 定位 `x-api-eid-token` 浏览器侧生成入口。
3. 完成 SDK 字符串层结构化还原。
4. 完成 Node.js 最小浏览器环境补齐。
5. 验证 `ParamsSign.signSync()` 可本地生成 `h5st`。
6. 将 `test.py` 中的旧 `h5st` 替换为运行时本地生成值。
7. 解决签名服务退出导致的 3456 端口连接拒绝问题。

### 限制

1. `x-api-eid-token` 不是离线固定值，不能保证长期有效。
2. Node 环境生成的 `h5st` 与完整浏览器环境生成值可能不同。
3. 不同浏览器、Cookie、时间和设备指纹可能导致结果不同。
4. Cookie 或 token 过期时，接口可能返回 `403` 或空数据。
5. 本报告不包含绕过登录、挑战或服务端风控的方案。

## 11. 安全建议

1. 不要将包含登录 Cookie 或 token 的 `test.py` 提交到公开仓库。
2. 不要打印完整 URL，因为 URL 中包含 `h5st` 和 `x-api-eid-token`。
3. 建议将 token 和 Cookie 改为本地私有配置或环境变量。
4. token 失效后，从已登录浏览器重新执行请求获取新值。
5. 保持 `functionId`、body 序列化顺序和时间戳口径与签名输入一致。
